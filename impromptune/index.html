Your agent's prompts were written by hand.

Impromptune rewrites them against your labelled data — and tells you the score on rows the search never saw.

Improve your agent Quickstart

You changed a prompt. Did it help?

Almost every prompt in production got there the same way: someone tried a wording, it looked better in three examples, and it shipped. That is not a measurement, and it does not survive the next model upgrade.

No baseline

Without a score for the prompt you already have, “better” is a feeling. Impromptune's first act is a baseline run: your prompts exactly as written, scored on your rows.

No hold-out

Tune against the same examples you judge with and you will always look good. Every run keeps rows back that the search never touches, and reports that number separately.

No record

Which prompt is actually live? What did it answer last Tuesday, and why? A published version is immutable, and every served request is traced.

How it works

1

Draw the program

Drag prompts onto a canvas and connect them. One prompt summarizes, another classifies, a third drafts the reply. A prompt with two or more outgoing edges becomes a router: the model picks which way the work goes. The whole thing is your program — Impromptune does not invent one for you.

A two-prompt program: summarize, then route. The dashed edge feeds the Evaluate block.
2

Bring labelled rows

A CSV or JSONL with your inputs and the right answer. Fifty rows is enough to start. Map the columns to the placeholders in your prompts, pick the label column, and run a pilot: twelve rows that measure the baseline, the model's own run-to-run noise, and what a full run will cost — before a cent is committed.

3

Let it search

Each round shows a reflection model a handful of the current best prompt's failures and asks for a rewrite. The rewrite is checked on a small batch first, and only earns a full evaluation if it beats its parent on the same rows. Everything is kept: the tree of attempts, each prompt diffed against its parent, and the rows the reflector was shown.

A run: best-so-far with noise bands on the left, the search tree on the right. Click any node to read its diff.
4

Publish and serve

Publish the node you like as a version: an immutable snapshot of the prompts, the models, the external steps and the score it earned. It gets an endpoint and an API key. Every request through it is traced, and corrections you record on those traces become the next dataset.

It can call your systems

A prompt can only classify what it can see. A step is a node that is not part of the program — an external call the optimizer never rewrites — that fetches what the prompts need.

Connect, don't paste

Where a provider supports it, you authorise Impromptune from inside your own account and revoke it there too. The HubSpot contact lookup that ships in the library is a real OAuth connection to a real CRM, not a mock. Where there is no app to connect to, paste a key instead.
How a step signs in →

Frozen to train, live to serve

Evaluation reads a snapshot taken when the row was captured; production calls the service live. That is a correctness decision, not a cost one: a ticket was labelled escalation because the customer had two tickets open that day. Re-fetching six weeks later optimizes against a moving target.
Why freezing →

A step is validated before you spend anything. Coverage, stability, leakage, redundancy and whether each field predicts the label better than chance — a permutation test and some arithmetic over columns, costing zero model calls. On the worked entitlement example the checks recovered the labelling rule from the columns alone, and correctly called one field redundant given another: dropping it cost nothing on the hold-out and saved two template tokens. What a run actually reports

A hold-out number, with error bars

Not the best score it saw, which is the maximum of a noisy sample and always flatters. The score of the chosen prompt on rows kept back, with the standard error next to it.

A front, not a winner

Accuracy against prompt length. Sometimes the shortest prompt within a point of the best is the one worth shipping, and you can only decide that by seeing both.

A per-class table

Aggregate accuracy hides the class that is 0 for 8. The breakdown is on the run page, because an average that moved for one reason is not an improvement.

What this is not

Not fine-tuning

Nothing here touches weights. The artefact is a prompt you can read, paste elsewhere, and keep after you stop paying us.

Not an agent framework

Nothing decides its own goals or writes its own code. You draw the program; the optimizer only rewrites the wording inside the boxes you drew.

Not a marketplace

Steps are manifests we curate. Nobody else publishes code that runs on our box — or on yours.

Not a guarantee

The search reports a measured number with its uncertainty. Sometimes the honest answer is that your prompt was already good, and we would rather show you that than a made-up win.
